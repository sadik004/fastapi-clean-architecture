## 1. Concepts Covered Today
- **SQLAlchemy 2.0 Declarative ORM Mapping (`app/models/user.py`)**:
  - Defined `UserModel(Base)` inheriting from our enterprise declarative base `Base(AsyncAttrs, DeclarativeBase)`.
  - Used modern SQLAlchemy 2.0 strict typing annotations with `Mapped[...]` and `mapped_column(...)`:
    - `id: Mapped[int] = mapped_column(primary_key=True, autoincrement=True)`
    - `email: Mapped[str] = mapped_column(String(255), unique=True, index=True, nullable=False)`
    - `full_name: Mapped[str] = mapped_column(String(255), nullable=False)`
    - `hashed_password: Mapped[str] = mapped_column(String(255), nullable=False)`
    - `role: Mapped[str] = mapped_column(String(50), nullable=False, default="user")`
    - `is_active: Mapped[bool] = mapped_column(Boolean, nullable=False, default=True)`
    - `created_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now(), nullable=False)`
    - `updated_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now(), onupdate=func.now(), nullable=False)`
  - Re-exported `UserModel` in `app/models/__init__.py` to ensure discovery by Alembic `target_metadata = Base.metadata`.
- **Async Alembic Migration Engine (`alembic/env.py` & `alembic.ini`)**:
  - Initialized Alembic with async template (`alembic init -t async alembic`).
  - Configured `alembic.ini` without hardcoded connection strings, binding `sqlalchemy.url` dynamically via `get_settings().database_url` in `alembic/env.py`.
  - Bound `target_metadata = Base.metadata`.
  - Configured `render_as_batch=True` on `context.configure()` for cross-database DDL compatibility (specifically SQLite ALTER TABLE limitations).
  - Configured thread offloading in `run_migrations_online()` to prevent `RuntimeError: asyncio.run() cannot be called from a running event loop` when migrations are invoked from async test suites or application lifecycle scripts.
- **Bi-Directional Migration Lifecycle & Programmatic Helpers (`app/core/database.py`)**:
  - Generated initial autogenerated revision `e25bf437c78f_create_users_table.py` with idempotent upgrade (`op.create_table('users', ...)`) and atomic downgrade (`op.drop_table('users')`).
  - Implemented programmatic helpers `apply_migrations(target_revision="head")` and `rollback_migration(target_revision="-1")` using Alembic `command.upgrade` and `command.downgrade`.
  - Re-exported migration helpers in `app/core/dependencies.py`.
- **Deprecation of `Base.metadata.create_all()` in Production**:
  - Removed `Base.metadata.create_all()` from `app/main.py` application lifespan.
  - Replaced it with an async database connectivity probe (`select(1)`) while delegating all DDL lifecycle management to version-controlled Alembic migrations.
- **Automated Schema Drift Detection & Metadata Cleanliness Contract**:
  - Implemented automated schema drift testing using `alembic.autogenerate.compare_metadata(migration_context, Base.metadata)`.
  - Isolated test-only entities in `tests/test_database_async_setup.py` by subclassing a dedicated `Day15TestBase` to prevent pollution of production `Base.metadata`.

## 2. DSA Time & Space Complexity Enforced
- **Index Lookups on Users Table**:
  - `email` column indexed via B-Tree index: strictly $\mathcal{O}(\log n)$ search, insert, and delete.
  - Primary key `id` lookup: strictly $\mathcal{O}(1)$ clustered index lookup in SQLite/PostgreSQL.
- **Alembic Version Resolution**:
  - Target migration revision lookups: $\mathcal{O}(1)$ hash map lookup of revision IDs in Alembic's DAG.
- **Metadata Registration**:
  - Model discovery into `Base.metadata.tables`: $\mathcal{O}(1)$ dictionary registration during Python import time.
