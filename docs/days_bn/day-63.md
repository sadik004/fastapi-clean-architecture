# ডে ৬৩: এক্সপোনেনশিয়াল ব্যাক-অফ উইথ জিটার আর্কিটেকচার (থান্ডারিং হার্ড ও রিট্রাই স্টর্ম প্রতিরোধ)

## ১. আমরা কী বানিয়েছি? (Mandatory Section 1)

আজকে **ডে ৬৩**-তে আমরা এডাব্লিউএস (AWS) আর্কিটেকচারাল স্ট্যান্ডার্ড অনুযায়ী প্রোডাকশন-গ্রেড **এক্সপোনেনশিয়াল ব্যাক-অফ উইথ জিটার (Exponential Backoff with Jitter)** রেজিলিয়েন্স ইঞ্জিন তৈরি করেছি। 

আমরা যা যা ডেভেলপ করেছি:
1. **কোর ব্যাক-অফ ও জিটার ইঞ্জিন (`app/core/resilience/backoff.py`)**:
   - $\mathcal{O}(1)$ গাণিতিক অ্যালগরিদমে চারটি স্ট্র্যাটেজি সম্পন্ন `calculate_backoff` ফাংশন:
     - **Full Jitter (AWS Canonical)**: $\text{delay} = \text{random.uniform}(0, \min(\text{max\_delay}, \text{base\_delay} \times 2^{\text{attempt}}))$। এটি ট্রাফিককে সময়ের অক্ষ বরাবর সর্বোচ্চ ডেসিনক্রোনাইজ করে।
     - **Equal Jitter**: ৫০% সময় নিশ্চিত ঘুম এবং বাকি ৫০% সময় র্যান্ডমাইজেশন ($\text{temp}/2 + \text{uniform}(0, \text{temp}/2)$)।
     - **Decorrelated Jitter**: পূর্ববর্তী ডিলের ওপর ভিত্তি করে পরবর্তী ডিলির ডায়নামিক স্কেলিং ($\min(\text{max\_delay}, \text{uniform}(\text{base\_delay}, \text{prev\_delay} \times 3))$)।
     - **No Jitter**: খাঁটি ডিটারমিনিস্টিক এক্সপোনেনশিয়াল গ্রোথ (বেঞ্চমার্কিংয়ের জন্য)।
   - অ্যাসিঙ্ক্রোনাস রিট্রাই ডেকোরেটর ও এক্সিকিউশন র‍্যাপার (`@retry_with_backoff`):
     - ট্রানজিয়েন্ট নেটওয়ার্ক বা সার্ভিস ডাউনটাইমে (`ServiceUnavailableException`, `TimeoutError`) স্বয়ংক্রিয় রিট্রাই।
     - প্রতিটি ফেইলিউরে জিটারড নন-ব্লকিং স্লিপ (`await asyncio.sleep(delay)`)।
     - রিট্রাই লিমিট শেষ হলে মূল এক্সেপশন রেইজ করা।
     - নন-রিট্রাইয়েবল এক্সেপশন (যেমন `ValueError`) তাৎক্ষণিক বাইপাস।
2. **রেজিলিয়েন্ট ডাউনস্ট্রিম সার্ভিস ইন্টিগ্রেশন (`app/services/resilient_third_party_service.py`)**:
   - `ResilientThirdPartyService` যা বাইরের থার্ড-পার্টি সার্ভিস (পেমেন্ট গেটওয়ে, এসএমএস গেটওয়ে) ফেইলিউর সিমুলেট করে এবং ব্যাক-অফ রিট্রাইয়ের মাধ্যমে স্বয়ংক্রিয়ভাবে সাকসেস রিকভারি প্রদর্শন করে।
3. **সিমুলেশন ও ডিস্ট্রিবিউশন এপিআই এন্ডপয়েন্ট (`app/routers/resilience_router.py`)**:
   - `POST /resilience/backoff/simulate-retry`: সাময়িক ব্যর্থতা এবং জিটারড রিট্রাই সাইকেল সিমুলেশন রেসপন্স।
   - `GET /resilience/backoff/distribution`: নির্দিষ্ট অ্যাটেম্পটের জন্য ১০০টি স্যাম্পল ডিলের র্যান্ডমাইজেশন ও ভ্যারিয়েন্স স্ট্যাটিস্টিক্স।
4. **সম্পূর্ণ টেস্ট স্যুট (`tests/test_backoff_jitter.py`)**:
   - গাণিতিক বাউন্ডস ভেরিফিকেশন, স্ট্যাটিস্টিক্যাল ভ্যারিয়েন্স টেস্ট, ডেকোরেটর ম্যাক্স রিট্রাই টেস্ট এবং এইচটিটিপি ইন্টিগ্রেশন টেস্ট।

3. **মেসেজ ব্রোকার কনজিউমার লুপ (Kafka / RabbitMQ Consumers):**

4. **মাইক্রোসার্ভিস ইন্টার-সার্ভিস আরপিসি (Inter-Service RPC / HTTP):**

2. **নেটওয়ার্ক কনজেশন ও ক্লাস্টার মেমোরি রক্ষা:**
   - ব্যাক-অফ ছাড়া টানা রিট্রাই করলে লোকাল সকেট পুল শেষ হয়ে যায় এবং সার্ভারের সিপিইউ ১০০% স্পাইক করে।
3. **গাণিতিক ফুল জিটার বনাম ইকুয়াল জিটার নির্বাচন:**

## ৭. আমাদের প্রজেক্টের আসল কোড ও লাইনের সহজ ব্যাখ্যা (Code & Breakdown)

### ১. `calculate_backoff` ইঞ্জিনের গাণিতিক রূপ
```python
def calculate_backoff(
    attempt: int,
    base_delay: float = 1.0,
    max_delay: float = 60.0,
    strategy: str = "full_jitter",
    previous_delay: float | None = None,
) -> float:
    # সূচকীয় বৃদ্ধি যেন মেমোরি বা ফ্লোট ওভারফ্লো না ঘটায় তাই attempt ৩০-এ ক্ল্যাম্প করা
    exp_factor = 2 ** min(max(0, attempt), 30)
    temp = min(max_delay, base_delay * exp_factor)

    if strategy == "full_jitter":
        # ০ থেকে temp-এর মধ্যে ইউনিফর্ম র‍্যান্ডম সংখ্যা
        return float(random.uniform(0.0, temp))

    if strategy == "equal_jitter":
        half = temp / 2.0
        # অর্ধেক নিশ্চিত ঘুম + বাকি অর্ধেক র‍্যান্ডম
        return float(half + random.uniform(0.0, half))

    if strategy == "decorrelated_jitter":
        prev = previous_delay if previous_delay is not None else base_delay
        # পূর্ববর্তী ডিলের ৩ গুণ পর্যন্ত ডায়নামিক রেঞ্জ
        return float(min(max_delay, random.uniform(base_delay, prev * 3.0)))

    return float(temp)
```

### ২. নন-ব্লকিং অ্যাসিঙ্ক রিট্রাই ডেকোরেটর
```python
def retry_with_backoff(
    func=None,
    *,
    max_retries: int = 3,
    base_delay: float = 0.1,
    max_delay: float = 5.0,
    strategy: str = "full_jitter",
    retry_exceptions=(ServiceUnavailableException, TimeoutError),
):
    def decorator(fn):
        @functools.wraps(fn)
        async def wrapper(*args, **kwargs):
            last_delay = None
            for attempt in range(max_retries + 1):
                try:
                    return await fn(*args, **kwargs)
                except retry_exceptions as exc:
                    if attempt >= max_retries:
                        raise  # সীমা শেষ, এক্সেপশন বাবল আপ করবে
                    
                    delay = calculate_backoff(
                        attempt=attempt,
                        base_delay=base_delay,
                        max_delay=max_delay,
                        strategy=strategy,
                        previous_delay=last_delay,
                    )
                    last_delay = delay
                    # নন-ব্লকিং স্লিপ যা ইভেন্ট লুপের অন্যান্য টাস্ককে চলতে দেয়
                    await asyncio.sleep(delay)
        return wrapper
    return decorator
```

| :--- | :--- | :--- | :--- |
| **Exponential Ceiling** | $\text{temp} = \min(M, B \times 2^k)$ | $\mathcal{O}(1)$ | $\mathcal{O}(1)$ |

## ৯. ইন্টারভিউ ও ভাইভা প্রশ্ন (Interview Questions & Answers)

### প্রশ্ন ১: Thundering Herd সমস্যা কী এবং সাধারণ Exponential Backoff কেন এটি পুরোপুরি সমাধান করতে পারে না?
**উত্তর:** যখন কোনো কেন্দ্রীয় সিস্টেম সাময়িক ফেইল করে আবার অনলাইনে ফিরে আসে, তখন সমস্ত ক্লায়েন্ট যদি একসাথে রিকোয়েস্ট পাঠায় তবে তাকে Thundering Herd বলা হয়।  
সাধারণ এক্সপোনেনশিয়াল ব্যাক-অফে প্রতিটি ক্লায়েন্ট একই সূত্র ($B \times 2^k$) মেনে চলে। ফলে প্রতি ব্যর্থতার পর তারা প্রত্যেকে ঠিক একই সময়ে (যেমন ১ম ব্যর্থতায় ২য় সেকেন্ডে, ২য় ব্যর্থতায় ৪র্থ সেকেন্ডে) রিট্রাই পাঠায়। এর ফলে ট্রাফিক ডেসিনক্রোনাইজ না হয়ে নিয়মিত বিরতিতে বড় বড় ট্রাফিক স্পাইক তৈরি করে। তাই ব্যাক-অফের সাথে র‍্যান্ডম জিটার যোগ করা অপরিহার্য।

### প্রশ্ন ২: AWS আর্কিটেকচারে Full Jitter-কে Equal Jitter-এর চেয়ে কেন বেশি অগ্রাধিকার দেওয়া হয়?
**উত্তর:** Full Jitter-এ স্লিপ টাইমিং ০ থেকে সর্বোচ্চ সীমা পর্যন্ত সম্পূর্ণরূপে উন্মুক্ত থাকে ($\mathcal{U}(0, \text{temp})$)। এতে ক্লায়েন্টদের কাজের বিস্তার সময়ের পুরো পরিসরে সবচেয়ে বেশি সমানভাবে ছড়িয়ে পড়ে (Maximum Entropy & Desynchronization)। অন্যদিকে Equal Jitter-এ একটি নির্দিষ্ট সময় পর্যন্ত সব ক্লায়েন্ট ঘুমাতে বাধ্য থাকে, ফলে সেই নির্দিষ্ট সময়ের পর পুনরায় ট্রাফিক ঘনীভূত হওয়ার সামান্য সম্ভাবনা থেকে যায়।
