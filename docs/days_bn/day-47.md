## ১. আমরা কী বানিয়েছি? (What did we build?)
আজ আমরা OWASP API Security Top 10-এর সবচেয়ে মারাত্মক ৩টি সাইবার আক্রমণ—**SSRF (Server-Side Request Forgery)**, **CORS মিসকনফিগারেশন**, এবং **পাথ ট্রাভার্সাল ইনজেকশন (Path Traversal / Directory Escape)**—এর বিরুদ্ধে শক্তিশালী প্রোডাকশন-গ্রেড সিকিউরিটি ফায়ারওয়াল ও স্যানিটাইজেশন গার্ড তৈরি করেছি। এই আর্কিটেকচারটি পাইথনের `ipaddress` সিআইডিআর (CIDR) ব্লকার দিয়ে এডব্লিউএস/জিসিপি ক্লাউড মেটাডাটা (`169.254.169.254`) ও ইন্টারনাল নেটওয়ার্কে অনুপ্রবেশ আটকে দেয়, ক্রেডেনশিয়াল সহ ওয়াইল্ডকার্ড CORS স্থায়ীভাবে নিষিদ্ধ করে এবং নাল-বাইট (`\x00`) সহ ডিরেক্টরি ট্রাভার্সাল ভেক্টর স্বয়ংক্রিয়ভাবে নিষ্ক্রিয় করে।

## 🚀 প্রোডাকশনে ঠিক কখন ব্যবহার করব? (When to use in Production)
- **ওয়েবহুক ও ইমেজ ফেচার এপিআই (Webhooks / Image Importer):** যখন আপনার ব্যাকএন্ড ইউজার-প্রদত্ত কোনো এক্সটার্নাল ইউআরএল (URL) থেকে ছবি, পিডিএফ বা ডাটা ডাউনলোড করে আনার রিকোয়েস্ট পাঠায়।
- **মাল্টি-ডোমেন ফ্রন্টএন্ড-ব্যাকএন্ড যোগাযোগ (CORS):** যখন রিঅ্যাক্ট/নেক্সটজেএস ফ্রন্টএন্ড (`https://myapp.com`) থেকে ব্যাকএন্ড এপিআইতে কুকি বা Bearer টোকেন সহ কল আসে, কিন্তু থার্ড-পার্টি ফিশিং বা ভুয়া সাইট থেকে কল সম্পূর্ণ ব্লক করতে হবে।
- **ডকুমেন্ট ডাউনলোড ও ফাইল ম্যানেজমেন্ট:** ইউজার যখন ফাইলের নাম পাঠিয়ে ফাইল ডাউনলোড করে, তখন যেন সে সিস্টেমের ডিরেক্টরি টপকে `/etc/passwd` বা ডাটাবেস ব্যাকআপ ফাইল চুরি করতে না পারে।

## 🎯 কী কারণে বা কোন পরিস্থিতিতে ব্যবহার করব? (Why to use / Technical Triggers)
- **SSRF ক্লাউড মেটাডাটা ও ইন্টারনাল নেটওয়ার্ক চুরি রোধ:** ক্লাউড এনভায়রনমেন্টে হ্যাকাররা `http://169.254.169.254/latest/meta-data/iam/` রিকোয়েস্ট পাঠিয়ে সম্পূর্ণ এডব্লিউএস একাউন্টের আইএএম (IAM) রোল ও রুট ক্রেডেনশিয়াল চুরি করে নিত (যেমন Capital One এর কুখ্যাত হ্যাক)। এই ফায়ারওয়াল ক্লাউড মেটাডাটা এবং লোকালহোস্ট (`127.0.0.1`, `10.0.0.0/8`, `192.168.0.0/16`) সম্পূর্ণ ব্লক করে।
- **ব্রাউজার সাইবার অ্যাটাক প্রতিরোধ (Strict CORS):** অলস ডেভেলপাররা প্রায়ই `allow_origins=["*"]` দিয়ে দেয়। কিন্তু এর সাথে `allow_credentials=True` থাকলে যেকোনো ক্ষতিকারক ওয়েবসাইট ইউজারের ব্যাংক সেশন বা প্রোফাইল ডাটা রিড করে নিতে পারে। স্ট্রিক্ট হোয়াইটলিস্ট দিয়ে ব্রাউজার-লেভেলে এটি বন্ধ করা।
- **পাথ ট্রাভার্সাল ও নাল-বাইট ইনজেকশন ধ্বংস:** ইউজারের ইনপুট থেকে `../` বা `..\` এবং স্ট্রিং ট্রাঙ্কেশন আক্রমণকারী `\x00` (Null Byte) নিউট্রালাইজ করা।

## ২. বাস্তব জীবনের গল্প ও উপমা: ট্রোজান হর্স ও বোকা দারোয়ানের গল্প
কল্পনা করুন একটি অত্যন্ত সুরক্ষিত সুরক্ষিত দুর্গ:
- **SSRF আক্রমণ (বোকা দারোয়ান):** দুর্গের ভেতর সাধারণ জনতার ঢোকার অনুমতি নেই। দুর্গের গেটে একজন দারোয়ান আছে, যার কাজ হলো প্রজারা বাইরে থেকে কোনো চিঠি আনলে সে ভেতর থেকে রাজা বা রানীর জবাব নিয়ে এসে প্রজাকে দেবে। হ্যাকার দারোয়ানকে একটি খাম দিয়ে বলল, "দারোয়ান ভাই, এই খামটা দুর্গের ভেতরে থাকা কোষাগারের লকারের রক্ষীকে দিন এবং লকারের চাবিটা নিয়ে এসে আমায় দিন।" বোকা দারোয়ান যেহেতু ভেতরের মানুষ, তাই কোষাগারের রক্ষী কোনো প্রশ্ন না করেই চাবি দিয়ে দিল এবং দারোয়ান সেটা হ্যাকারের হাতে তুলে দিল! দারোয়ানকে ব্যবহার করে দুর্গের ভেতরের সম্পদ চুরি করাই হলো **SSRF**।
- **SSRF ফায়ারওয়াল (চালাক পরিদর্শক):** এখন গেটে একজন সিকিউরিটি অফিসার বসানো হলো। দারোয়ান চিঠি নেওয়ার আগে অফিসার দেখে চিঠিটি কার ঠিকানায় যাচ্ছে। যদি দেখে ঠিকানা দুর্গের ভেতরকার কোষাগার (`169.254.169.254` বা `127.0.0.1`), অফিসার সাথে সাথে চিঠি ছিঁড়ে ফেলে দারোয়ানকে আটকে দেয় এবং অ্যাক্সেস নিষিদ্ধ করে!

## ৩. এটা না বানালে কী মহাবিপদ হতো? (The Production Disaster Without It)
১. **সম্পূর্ণ ক্লাউড একাউন্ট হাইজ্যাক:** এডব্লিউএস, জিসিপি বা অ্যাজুর ক্লাউডে চলা কোনো এপিআইতে যদি সাধারণ ইমেজ ডাউনলোডার থাকে এবং SSRF ডিফেন্স না থাকে, হ্যাকার মাত্র ১টি রিকোয়েস্টে ক্লাউড ভেনডরের ইনস্ট্যান্স মেটাডাটা এপিআই (`http://169.254.169.254`) কল করে পুরো ক্লাউড ইনফ্রাস্ট্রাকচারের সিক্রেট কি চুরি করে পুরো ডেটাবেস মুছে দিতে পারত।
২. **ইন্টারনাল রেডিস ও ডাটাবেস ধ্বংস:** ক্লাউডের প্রাইভেট ভিপিসি (VPC)-তে থাকা রেডিস ক্যাশ বা পোস্টগ্রেস ডাটাবেসে বাইরের ইন্টারনেট থেকে সরাসরি ঢোকা যায় না। কিন্তু SSRF দিয়ে হ্যাকার আপনার ফাস্টএপিআই সার্ভারকে প্রক্সি বানিয়ে ইন্টারনাল রেডিসে `FLUSHALL` কমান্ড পাঠিয়ে সমস্ত ক্যাশ ও ডেটা ধ্বংস করে দিত।
৩. **সেনসিটিভ কনফিগ ফাইল চুরি:** পাথ ট্রাভার্সাল প্রটেকশন না থাকলে `/files/download?filename=../../../../etc/passwd` বা `../../.env` পাঠিয়ে হ্যাকার ডাটাবেসের পাসওয়ার্ড ও সিক্রেট কি নামিয়ে নিত।

## ৪. আমাদের প্রজেক্টের আসল কোড ও কোডের লাইন-বাই-লাইন সহজ ব্যাখ্যা

### ৪.১ SSRF ফায়ারওয়াল ও আইপি রেঞ্জ ব্লকার (`app/core/ssrf_protection.py`)
```python
import ipaddress
import socket
from urllib.parse import urlsplit
from app.core.exceptions import SSRFSecurityException

# নিষিদ্ধ আইপি নেটওয়ার্কের তালিকা (লুপব্যাক, প্রাইভেট ও ক্লাউড মেটাডাটা)
FORBIDDEN_IP_NETWORKS = (
    ipaddress.ip_network("127.0.0.0/8"),      # IPv4 Loopback
    ipaddress.ip_network("10.0.0.0/8"),       # RFC 1918 Private
    ipaddress.ip_network("172.16.0.0/12"),    # RFC 1918 Private
    ipaddress.ip_network("192.168.0.0/16"),   # RFC 1918 Private
    ipaddress.ip_network("169.254.0.0/16"),   # AWS/GCP/Azure Cloud Metadata (IMDS)
    ipaddress.ip_network("::1/128"),          # IPv6 Loopback
    ipaddress.ip_network("fc00::/7"),         # IPv6 ULA Private
    ipaddress.ip_network("fe80::/10"),        # IPv6 Link-Local
)

def validate_safe_url(url: str) -> str:
    parsed = urlsplit(url)
    scheme = (parsed.scheme or "").lower()
    
    # ১. কেবল http এবং https স্কিম অনুমোদিত (file://, gopher:// সরাসরি নিষিদ্ধ)
    if scheme not in ("http", "https"):
        raise SSRFSecurityException(f"Prohibited URL scheme '{scheme}'. Only HTTP and HTTPS are permitted.")
    
    hostname = parsed.hostname
    if not hostname:
        raise SSRFSecurityException("Target URL must specify a valid destination hostname.")
    
    # ২. ডিএনএস রেজোলিউশন ও আইপি এক্সট্রাকশন
    resolved_ips = []
    try:
        resolved_ips.append(ipaddress.ip_address(hostname.strip("[]")))
    except ValueError:
        for item in socket.getaddrinfo(hostname, None):
            ip_str = item[4][0]
            resolved_ips.append(ipaddress.ip_address(ip_str))
    
    # ৩. ডেস্টিনেশন আইপি নিষিদ্ধ কোনো ব্লকে পড়ে কিনা তা O(1) ম্যাথে যাচাই
    for ip in resolved_ips:
        if ip.is_loopback or ip.is_private or ip.is_link_local:
            raise SSRFSecurityException(f"SSRF security violation: Destination host '{hostname}' resolves to forbidden IP '{ip}'.")
        for net in FORBIDDEN_IP_NETWORKS:
            if ip in net:
                raise SSRFSecurityException(f"SSRF security violation: Destination resolves to forbidden CIDR block '{net}'.")
    return url
```
**লাইন-বাই-লাইন ব্যাখ্যা:**
1. `scheme not in ("http", "https")`: অ্যাটাকাররা যাতে `file:///etc/passwd` বা `gopher://` প্রোটোকল ব্যবহার করে সার্ভারের লোকাল সকেট বা ফাইলে হাত না দিতে পারে।
2. `socket.getaddrinfo`: হ্যাকার যদি সরাসরি আইপি না দিয়ে ডোমেইন নাম দেয় (যেমন: `localhost` বা কোনো ডোমেন যা ইন্টারনাল আইপিতে পয়েন্ট করে), এটি ডিএনএস কুয়েরি চালিয়ে আসল আইপি বের করে ফেলে (DNS Rebinding রোধ)।
3. `ip in net`: পাইথনের `ipaddress` মডিউল বিটওয়াইজ সাবনেট মাস্কিং দিয়ে $\mathcal{O}(1)$ গাণিতিক সময়ে চেক করে আইপিটি ক্লাউড মেটাডাটা বা লোকাল নেটওয়ার্কে পড়েছে কিনা।

### ৪.২ পাথ ট্রাভার্সাল স্যানিটাইজেশন গার্ড (`app/core/sanitization.py`)
```python
import os
import re
from app.core.exceptions import PathTraversalException

_TRAVERSAL_PATTERN = re.compile(r"(\.\.[/\\]|[/\\])")

def sanitize_file_path(filename: str, strict: bool = False) -> str:
    # ১. নাল-বাইট ইনজেকশন ব্লক
    if "\x00" in filename:
        raise PathTraversalException("Security violation: Null byte injection (\\x00) detected.")
    
    # ২. নন-প্রিন্টেবল কন্ট্রোল ক্যারেক্টার ব্লক
    for ch in filename:
        if ord(ch) < 32:
            raise PathTraversalException("Security violation: Control character detected.")
            
    # ৩. ক্যানোনিকাল বেসনেম এক্সট্রাকশন ও ট্রাভার্সাল নিউট্রালাইজেশন
    base = os.path.basename(filename.replace("\\", "/"))
    clean = _TRAVERSAL_PATTERN.sub("", base).strip()
    
    if not clean or all(c == "." for c in clean):
        raise PathTraversalException(f"Security violation: Invalid filename '{filename}'.")
    return clean
```

## ৫. ডিএসএ ও নেটওয়ার্ক রেঞ্জ মেকানিক্স
- **আইপি সিআইডিআর রেঞ্জ মাস্কিং (IP CIDR Math):**
  - আইপি অ্যাড্রেস হলো ৩২-বিট (IPv4) বা ১২৮-বিট (IPv6) বাইনারি ইন্টিজার।
  - একটি আইপি কোনো সাবনেটে (`169.254.0.0/16`) আছে কিনা তা যাচাই করতে পাইথন বিটওয়াইজ মাস্কিং করে: `(ip_int & mask_int) == network_int`।
  - এটি কোনো লুপ বা অ্যারে স্ক্যান নয়—মাত্র ১টি সিপিইউ ক্লক সাইকেলে সম্পন্ন হওয়া বিশুদ্ধ $\mathcal{O}(1)$ অপারেশন ($< 0.01\text{ms}$)।
- **পাথ ক্যানোনিক্যালাইজেশন (Path Canonicalization):**
  - স্ট্রিং-এর ডিরেক্টরি সেপারেটরগুলোকে স্ট্যান্ডার্ডাইজ করে লিনাক্স ও উইন্ডোজ উভয়ের ব্যাকস্ল্যাশ (`\`) ও ফরোয়ার্ড স্ল্যাশ (`/`) থেকে ফাইলনেমটিকে নিরাপদে বের করে আনা হয় ($\mathcal{O}(N)$ স্ট্রিং টাইম)।

## ৬. ইন্টারভিউ ও ভাইভা প্রশ্ন

### প্রশ্ন ১: SSRF কী এবং কেন শুধুমাত্র ডোমেন নেম বা ব্ল্যাকলিস্ট চেক করাই যথেষ্ট নয়?
**উত্তর:**  
SSRF (Server-Side Request Forgery) হলো এমন একটি দুর্বলতা যেখানে আক্রমণকারী ভালনারেবল অ্যাপ্লিকেশন সার্ভারকে ব্যবহার করে ইন্টারনাল নেটওয়ার্ক, লোকালহোস্ট অথবা ক্লাউড মেটাডাটা সার্ভিসে রিকোয়েস্ট পাঠায়।  
শুধু ব্ল্যাকলিস্ট চেক করা ঝুঁকিপূর্ণ কারণ অ্যাটাকার বিভিন্ন কৌশল ব্যবহার করতে পারে:
1. **হেক্স বা অকটাল আইপি রিপ্রেজেন্টেশন:** `127.0.0.1`-এর বদলে `0177.0.0.1` বা `2130706433`।
2. **DNS Rebinding:** এমন একটি ডোমেন ব্যবহার করা যা বাইরের আইপি হিসেবে যাচাই হয় কিন্তু ঠিক রিকোয়েস্ট পাঠানোর মুহূর্তে ইন্টারনাল আইপিতে (`169.254.169.254`) পয়েন্ট করে।
তাই সঠিক পদ্ধতি হলো রিকোয়েস্ট পাঠানোর ঠিক আগে ডিএনএস রিজলভ করে সমস্ত আইপি এড্রেসকে সিআইডিআর ব্লকে $\mathcal{O}(1)$ বিটওয়াইজ মাস্কিং দিয়ে যাচাই করা।

### প্রশ্ন ২: CORS-এ `allow_origins=["*"]` এর সাথে `allow_credentials=True` একসাথে দিলে কী সমস্যা এবং ব্রাউজার কীভাবে প্রতিক্রিয়া দেখায়?
**উত্তর:**  
যদি কোনো সাইট `allow_origins=["*"]` এবং `allow_credentials=True` একসাথে অনুমতি দেয়, তবে ইন্টারনেটের যেকোনো ক্ষতিকারক ওয়েবসাইট (যেমন `evil.com`) ভিকটিমের ব্রাউজার থেকে ওই ব্যাকএন্ড এপিআইতে ব্যাকগ্রাউন্ডে কুকি বা অথেনটিকেশন টোকেন সহ রিকোয়েস্ট পাঠিয়ে সেনসিটিভ রেসপন্স ডাটা পড়ে নিতে পারে। আধুনিক ব্রাউজারগুলো এই কম্বিনেশন দেখলে স্বয়ংক্রিয়ভাবে রেসপন্স ব্লক করে এবং কনসোলে সিকিউরিটি এরর দেখায়। প্রোডাকশনে সর্বদা নির্দিষ্ট ফ্রন্টএন্ড ডোমেনের স্পষ্ট হোয়াইটলিস্ট ব্যবহার করতে হবে।
