# ডে ১০: ডিপেনডেন্সি লাইফসাইকেল ক্লিনআপ (The yield Mechanism, Two-Phase Context ও ট্রানজ্যাকশনাল টিয়ারডাউন)

> **তারিখ**: ২০২৬-০৯-০৮  
> **ভূমিকা**: জুনিয়র শিক্ষানবিস ব্যাকএন্ড ইঞ্জিনিয়ার  
> **মেন্টর ও লিড আর্কিটেক্ট**: ইউজার  
> **মূল দর্শন**: কোনো রিসোর্স যেন মেমোরিতে ড্যাংলিং অবস্থায় ঝুলন্ত না থাকে—FastAPI-এর `yield` মেকানিজম এবং `finally:` ব্লকের মাধ্যমে নিশ্চিত করুন টু-ফেজ ট্রানজ্যাকশন সেফটি এবং জিরো রিসোর্স লিক।

## ১. বাস্তব জীবনের রূপক: প্রিমিয়াম রেন্ট-এ-কার সার্ভিসের দুই ধাপের লাইফসাইকেল

কল্পনা করুন আপনি একটি হাই-এন্ড কার রেন্টাল (গাড়ি ভাড়া) এজেন্সি থেকে কয়েক ঘণ্টার জন্য একটি গাড়ি নিচ্ছেন:

1. **যাত্রার পূর্ববর্তী ধাপ (Pre-yield / Phase 1: Resource Acquisition)**:
   - কাউন্টারে গিয়ে আপনি চুক্তি স্বাক্ষর করেন। এজেন্সি আপনার জন্য একটি গাড়ি বরাদ্দ করে, একটি অনন্য বুকিং আইডি (`tx_id`) রেজিস্টার খাতায় লেখে এবং আপনাকে চাবিটি বুঝিয়ে দেয় (`tx = transaction_manager.begin()`)।
2. **আসল যাত্রা (Yield to Route Handler: Execution Phase)**:
   - এজেন্সি আপনাকে গাড়িটি বুঝিয়ে দিয়ে বলে, *"যান, আপনার কাজ সম্পন্ন করুন।"* (`yield tx`)। এই পর্যায়ে আপনি শহরে মিটিং করতে যাচ্ছেন, শপিং করছেন, বা কাউকে ড্রপ করছেন (রাউটার তার ডেটাবেজ বা মেমোরি অপারেশন সম্পন্ন করছে)।
3. **যাত্রার পরবর্তী ধাপ ও নিষ্পত্তি (Post-yield / Phase 2: Teardown & Finalization)**:
   - **কেস ১: সফল যাত্রা (Normal Flow)**:
     - আপনি সময়মতো গাড়ি অক্ষত অবস্থায় ফিরিয়ে আনলেন। এজেন্সি আপনার বুকিং সফলভাবে ক্লোজ করে এবং সিকিউরিটি ডিপোজিট রিলিজ করে (`TransactionStatus.COMMITTED`)।
   - **কেস ২: দুর্ঘটনা বা এক্সিডেন্ট (Exception / Error)**:
     - যাত্রাপথে যদি কোনো দুর্ঘটনা ঘটে বা যান্ত্রিক ত্রুটি দেখা দেয় (HTTPException বা সার্ভার ক্র্যাশ), এজেন্সি সাথে সাথে ইমার্জেন্সি ইনস্যুরেন্স ও টো-ট্রাক কল করে গাড়িটি উদ্ধার করে এবং জরিমানা বা ক্ষতিপূরণ হিসেব করে (`tx.rollback()`)।
   - **কেস ৩: বাধ্যতামূলক গ্যারেজ এন্ট্রি (Unconditional `finally:` Block)**:
     - যাই ঘটুক না কেন—আপনি মিষ্টি হেসে ফিরে আসুন কিংবা গাড়ি দুমড়ে-মুচড়ে যাক—এজেন্সির দায়িত্ব হলো গাড়িটিকে তার পার্কিং লটে পার্ক করানো, সার্ভিস খাতায় এন্ট্রি দেওয়া এবং সিস্টেম থেকে "ইন-ইউজ" ফ্ল্যাগ সরিয়ে ফেলা (`transaction_manager.close(tx)`)। কোনো অবস্থাতেই গাড়ির চাবি কাস্টমারের পকেটে ফেলে রাখা যাবে না!

এই রূপকটিই হলো আমাদের ডে ১০-এর **Generator Dependency with `yield`**। `yield`-এর আগের অংশ হলো রিসোর্স বরাদ্দ, `yield`-এর মাঝের অংশ হলো রাউটারের কাজ, আর `yield`-এর পরের `finally:` অংশ হলো জিরো-লিক গ্যারান্টিযুক্ত রিসোর্স ক্লিনআপ।

## ২. প্রোডাকশন সিস্টেমের বিপর্যয় ও পেছনের গল্প (The "Why" Behind The Architecture)

### বিপর্যয় ১: ডাটাবেজ কানেকশন পুল একজশন (Connection Pool Exhaustion Catastrophe)
প্রোডাকশনে সবচেয়ে পরিচিত এবং ভয়াবহ রাতের দুঃস্বপ্নগুলোর একটি হলো:
> *"ভোর ৪টায় অ্যালার্ম বাজল: ৫টি মাইক্রোসার্ভিস একসাথে ডাউন, ডাটাবেজ রেসপন্স করছে না, ক্লায়েন্টরা পাচ্ছে `504 Gateway Timeout`!"*

**কেন ঘটে এই বিপর্যয়?**  
ডেভেলপাররা রাউটার হ্যান্ডলারে কানেকশন ওপেন করেন:
```python
# ভয়াবহ এন্টি-প্যাটার্ন
@router.post("/checkout")
def checkout(payload: Order):
    db = get_db_connection()
    # এখানে কোনো ভ্যালিডেশন ফেইল করল বা HTTPException রেইজ হলো
    if not payload.items:
        raise HTTPException(400, "Cart empty") # <--- ক্র্যাশ! db.close() আর কল হলো না!
    db.save(payload)
    db.close()
```
যখনই কোনো রিকোয়েস্টে এক্সেপশন বা ভ্যালিডেশন এরর হয়, ফাংশনটি মাঝপথেই থেমে যায়। ফলে `db.close()` পর্যন্ত এক্সিকিউশন পৌঁছায় না। ১০০০টি এরর রিকোয়েস্ট আসার পর ডাটাবেজের সমস্ত কানেকশন পুল (Connection Pool) আটকে থাকে (`Dangling Connection`)। ডাটাবেজ নতুন কোনো বৈধ রিকোয়েস্ট গ্রহণ করতে পারে না—আর পুরো প্ল্যাটফর্ম ক্র্যাশ করে!

### বিপর্যয় ২: আনকমিটেড ডার্টি রিডস এবং টেবিল লকআউট
যদি কোনো ট্রানজ্যাকশন ওপেন হওয়ার পর এরর হ্যান্ডলিং না থাকে, তবে ডেটাবেজ ট্রানজ্যাকশনটিকে `IDLE IN TRANSACTION` অবস্থায় রেখে দেয়। এর ফলে রিলেশনাল টেবিলের ওপর রো-লেভেল বা টেবিল-লেভেল এক্সক্লুসিভ লক লেগে থাকে। অন্য কোনো ইউজার সেই টেবিলে রিড বা রাইট করতে পারে না, যার পরিণতি হলো ভয়াবহ **ডেডলক (Deadlock)**।

**আর্কিটেকচারাল প্রতিষেধক**:  
রাউটার হ্যান্ডলারদের কানেকশন বা ট্রানজ্যাকশন ম্যানুয়ালি ক্লোজ করার দায়িত্ব দেওয়া যাবে না। এই লাইফসাইকেল ম্যানেজমেন্ট পুরোপুরি ডিক্লেয়ারেটিভ ডিপেনডেন্সি লেয়ারে `yield` এবং `finally:` ব্লকের হাতে ন্যস্ত করতে হবে।

## ৩. আর্কিটেকচারাল ডিজাইন এবং টু-ফেজ জেনারেটর লাইফসাইকেল (Two-Phase Execution Model)

FastAPI পাইথনের стандарт জেনারেটর প্রোটোকল (`Generator[YieldType, SendType, ReturnType]`) এবং `AsyncExitStack`-এর মাধ্যমে ডিপেনডেন্সির টু-ফেজ এক্সিকিউশন পরিচালনা করে:

```
[Incoming HTTP Request]
         │
         ▼
┌─────────────────────────────────────────────────────────┐
│ Phase 1: Pre-yield (Acquisition)                        │
│ - tx = transaction_manager.begin()                      │
│ - tx_id তৈরি ও _active_transactions ডিকশনারিতে রেজিস্টার │
└────────────────────────┬────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────┐
│ Yield Point: Context Handover                           │
│ - yield tx (রাউটার হ্যান্ডলারকে এক্সিকিউশন হস্তান্তর)   │
└────────────────────────┬────────────────────────────────┘
                         │
        ┌────────────────┴────────────────┐
        │                                 │
        ▼                                 ▼
[Handler Return: 200 OK]        [Handler Error: 4xx/5xx]
        │                                 │
        │                                 ▼
        │                       ┌─────────────────────────┐
        │                       │ Exception Catch Block   │
        │                       │ - tx.rollback()         │
        │                       │ - staged actions মুছা    │
        │                       │ - re-raise (raise)      │
        │                       └─────────┬───────────────┘
        ▼                                 │
┌─────────────────────────┐               │
│ Normal Post-yield       │               │
│ - tx.commit()           │               │
└───────────┬─────────────┘               │
            │                             │
            └──────────────┬──────────────┘
                           ▼
┌─────────────────────────────────────────────────────────┐
│ Phase 2: Unconditional Teardown (finally:)              │
│ - tx.close()                                            │
│ - transaction_manager.close(tx)                         │
│ - _active_transactions থেকে O(1) আনরেজিস্টার            │
│ - active_count == 0 গ্যারান্টি (জিরো রিসোর্স লিক)        │
└─────────────────────────────────────────────────────────┘
```

### ট্রানজ্যাকশন স্ট্যাটাস মেশিন
আমাদের `ScopedTransactionContext` একটি স্পষ্ট স্টেট মেশিনের মাধ্যমে পরিচালিত হয়:
- `ACTIVE`: ট্রানজ্যাকশন শুরু হয়েছে, নতুন অ্যাকশন স্টেজ (`stage()`) করা সম্ভব।
- `COMMITTED`: রিকোয়েস্ট সফলভাবে সম্পন্ন হয়েছে, পরিবর্তনগুলো পার্মানেন্ট করা হয়েছে।
- `ROLLED_BACK`: কোনো এক্সেপশন ঘটায় ট্রানজ্যাকশনের সমস্ত স্টেজড অ্যাকশন বাতিল ও পরিষ্কার করা হয়েছে।
- `CLOSED`: ট্রানজ্যাকশন সম্পূর্ণ বন্ধ এবং রেজিস্ট্রি থেকে আনরেজিস্টার্ড।

## ৪. কোডবেসের বাস্তব কোড ব্যবচ্ছেদ (Line-by-Line Grounded Code Walkthrough)

আসুন আমাদের আসল প্রোডাকশন কোডবেস `app/core/dependencies.py` থেকে সরাসরি লাইন বাই লাইন ব্যবচ্ছেদ করি:

### ক. `TransactionManager` এবং `ScopedTransactionContext` (`app/core/dependencies.py`)

```python
class ScopedTransactionContext:
    """একটি স্কোপড ইউনিট অব ওয়ার্ক ট্রানজ্যাকশন যা স্টেজড অপারেশন ও লাইফসাইকেল ট্র্যাক করে।"""

    def __init__(self, tx_id: str) -> None:
        self.tx_id: str = tx_id
        self.status: TransactionStatus = TransactionStatus.ACTIVE
        self.staged_actions: list[str] = []
        self.is_closed: bool = False
        self.created_at: float = time.perf_counter()
        self.duration_ms: float = 0.0

    def stage(self, action: str) -> None:
        """অ্যাক্টিভ ট্রানজ্যাকশনে একটি মিউটেশন অ্যাকশন স্টেজ করা।"""
        if self.status != TransactionStatus.ACTIVE:
            raise RuntimeError(f"Cannot stage actions on {self.status.value} transaction {self.tx_id}")
        self.staged_actions.append(action)

    def commit(self) -> None:
        """স্টেজড অ্যাকশনগুলো কমিট করে স্ট্যাটাস COMMITTED মার্ক করা।"""
        if self.status == TransactionStatus.ACTIVE:
            self.status = TransactionStatus.COMMITTED

    def rollback(self) -> None:
        """স্টেজড অ্যাকশন পরিষ্কার করে স্ট্যাটাস ROLLED_BACK মার্ক করা।"""
        if self.status == TransactionStatus.ACTIVE:
            self.status = TransactionStatus.ROLLED_BACK
            self.staged_actions.clear()

    def close(self) -> None:
        """নিঃশর্তভাবে ট্রানজ্যাকশন বন্ধ করা এবং এক্সিকিউশন ডিউরেশন হিসাব করা।"""
        if self.status == TransactionStatus.ACTIVE:
            self.rollback()
        self.is_closed = True
        self.duration_ms = (time.perf_counter() - self.created_at) * 1000.0
```
- **লাইন ২১৮-২২৩**: ট্রানজ্যাকশন যদি `ACTIVE` না থাকে (যেমন অলরেডি রোলব্যাক বা কমিটেড), তবে সেখানে নতুন কিছু স্টেজ করতে গেলে তাৎক্ষণিক `RuntimeError` ছুড়ে দিয়ে ইনভ্যারিয়েন্ট রক্ষা করা হয়।
- **লাইন ২৩৭-২৪০**: `close()` মেথডে একটি ডিফেন্সিভ গার্ড রাখা হয়েছে: যদি কোনো কারণে ট্রানজ্যাকশন এখনো `ACTIVE` থেকে যায়, তবে ফোর্সড `rollback()` চালিয়ে তারপর ক্লোজ করা হয়।

### খ. টু-ফেজ জেনারেটর ডিপেনডেন্সি (`get_transaction_context`)

```python
def get_transaction_context() -> Generator[ScopedTransactionContext, None, None]:
    """টু-ফেজ জেনারেটর ডিপেনডেন্সি যা স্বয়ংক্রিয় টিয়ারডাউন নিশ্চিত করে।
    - Pre-yield (Phase 1): একটি আইসোলেটেড ট্রানজ্যাকশন শুরু করে।
    - Yield: রাউটার হ্যান্ডলারের হাতে এক্সিকিউশন ছেড়ে দেয়।
    - Post-yield (Phase 2):
        * স্বাভাবিক রিটার্নে: কমিট করে।
        * এক্সেপশনে: রোলব্যাক করে এবং এক্সেপশন পুনরায় ছুড়ে দেয় (raise)।
        * finally ব্লকে: ট্রানজ্যাকশন ক্লোজ ও আনরেজিস্টার নিশ্চিত করে।
    """
    tx = transaction_manager.begin()  # Phase 1: শুরু
    try:
        yield tx                      # Handover to Endpoint
        if tx.status == TransactionStatus.ACTIVE:
            tx.commit()               # Normal Phase 2: Commit
    except Exception:
        tx.rollback()                 # Error Phase 2: Rollback
        raise                         # Exception Transparency
    finally:
        transaction_manager.close(tx) # Unconditional Teardown
```
- **লাইন ২৮৮**: `tx = transaction_manager.begin()`—রিকোয়েস্টের শুরুতে ইন-মেমোরি ট্রানজ্যাকশন রেজিস্টার হয়।
- **লাইন ২৯০**: `yield tx`—এখানে FastAPI এক্সিকিউশন পজ (pause) করে কন্ট্রোল রাউটার ফাংশনের কাছে পৌঁছে দেয়।
- **লাইন ২৯৩-২৯৫**: রাউটারের কোডে কোনো এরর ঘটলে FastAPI ইন্টারনালি জেনারেটরে এক্সেপশন ছুড়ে দেয় (`gen.throw()`)। `except Exception:` ব্লক সেটি ধরে রোলব্যাক সম্পন্ন করে এবং `raise` দিয়ে এক্সেপশনটিকে অক্ষত রেখে ওপরের গ্লোবাল এক্সেপশন হ্যান্ডলারের কাছে পাঠিয়ে দেয়।
- **লাইন ২৯৬-২৯৭**: `finally:` ব্লক—বিশ্ব ধ্বংস হয়ে গেলেও এই ব্লকটি এক্সিকিউট হবেই! এটি `transaction_manager.close(tx)` কল করে অ্যাক্টিভ ম্যাপ থেকে ট্রানজ্যাকশন রিমুভ করে মেমোরি লিক শূন্যে নামায়।

### গ. অডিট টাইমিং ও রিকোয়েস্ট ট্র্যাকিং ডিপেনডেন্সি (`track_request_lifecycle`)

```python
def track_request_lifecycle() -> Generator[RequestLifecycleContext, None, None]:
    """ল্যাটেন্সি পরিমাপ এবং রিকোয়েস্ট অডিট লগ তৈরির জন্য জেনারেটর ডিপেনডেন্সি।"""
    trace_id = uuid.uuid4().hex[:16]
    ctx = RequestLifecycleContext(trace_id=trace_id)
    try:
        yield ctx
    finally:
        ctx.complete()  # রিকোয়েস্ট শেষ হওয়া মাত্র সময় রেকর্ড করা হয়
```

## ৬. বাস্তব বাগ ও আরসিএ ব্যবচ্ছেদ (Real RCA: Root Cause Analysis)

আমাদের প্রজেক্টের আসল আরসিএ ফাইল `docs/rca/day-10_unseeded_auth_fixture_and_yield_teardown.md` থেকে দুটি শিক্ষণীয় সমস্যা বিশ্লেষণ করা হলো:

### ইনসিডেন্ট ১: আনসীডেড অথেন্টিকেশন ফিক্সচার ডিপেনডেন্সি ট্র্যাপ

#### ফেইল করা টেস্ট কোড:
```python
# tests/test_dependency_yield_lifecycle.py
def test_user_not_found_triggers_rollback(
    client: TestClient,
    admin_auth_headers: dict[str, str],  # মারাত্মক ভুল: admin_user ফিক্সচার মিসিং!
) -> None:
    response = client.delete("/users/999999", headers=admin_auth_headers)
    assert response.status_code == status.HTTP_404_NOT_FOUND  # FAILED: Got 401 Unauthorized!
```

#### রুট কজ (Root Cause):
`admin_auth_headers` টেস্ট ক্লায়েন্টকে হেডার পাঠায় `{"X-API-Key": settings.admin_api_key}`। কিন্তু আমাদের ডিপেনডেন্সি `get_current_user` শুধু এপিআই কি মেলায় না, সে মেমোরি রিপোজিটরিতে গিয়ে দেখে যে ওই নামের ইউজার ডেটাবেজে সীড করা আছে কিনা (`service.get_user_by_username(...)`)। যেহেতু টেস্ট সিগনেচারে `admin_user` ফিক্সচার ছিল না, তাই রিপোজিটরিতে কোনো অ্যাডমিন রেকর্ডই তৈরি হয়নি! ফলে রিকোয়েস্ট রাউটার এবং সার্ভিস পর্যন্ত পৌঁছানোর অনেক আগেই সিকিউরিটি গেটে `401 Unauthorized` হিসেবে বাতিল হয়ে যায়।

#### আর্কিটেকচারাল সমাধান:
যে টেস্টে প্রিভিলেজড ক্রেডেনশিয়াল প্রয়োজন, সেখানে ক্রেডেনশিয়াল হেডার ফিক্সচারের সাথে স্টেট সীডিং ফিক্সচারকে কাপল্ড (Coupled) হিসেবে ডিক্লেয়ার করতে হবে:
```python
def test_user_not_found_triggers_rollback(
    client: TestClient,
    admin_user: dict[str, Any],          # ডাটাবেজে ইউজার সত্ত্বা নিশ্চিত করে
    admin_auth_headers: dict[str, str],  # অথরাইজেশন হেডার পাঠায়
) -> None:
    response = client.delete("/users/999999", headers=admin_auth_headers)
    assert response.status_code == status.HTTP_404_NOT_FOUND
```

---

### ইনসিডেন্ট ২: `finally:` ব্লক ছাড়া ডিপেনডেন্সিতে ঝুলন্ত কানেকশন ট্র্যাপ

#### ক্র্যাশ সৃষ্টিকারী অ্যান্টি-প্যাটার্ন:
```python
# app/core/dependencies.py
def get_transaction_context():
    tx = transaction_manager.begin()
    yield tx
    tx.commit()
    # এখানে কোনো finally: ব্লক নেই!
```

#### রুট কজ (Root Cause):
যদি রাউটার বা কোনো সার্ভিস মেথডে `HTTPException(404)` রেইজ হয়, পাইথন জেনারেটরের ভেতর সেই এক্সেপশনটি প্রপাগেট করে। `yield tx`-এর ঠিক পরের লাইনে থাকা `tx.commit()` কোড আর রান হয় না। যদি টিয়ারডাউন কোডটি `finally:` ব্লকের ভেতরে না থাকে, তবে কোড অবিলম্বে অ্যাবর্ট হয়। ফলস্বরূপ `tx` আজীবনের জন্য `_active_transactions`-এ সক্রিয় থেকে যায় এবং মেমোরি লিক ঘটায়।

#### আর্কিটেকচারাল সমাধান:
কখনোই `finally:` ব্লক বাদ দেবেন না। রিসোর্স ফ্রি করার কোড অবশ্যই `finally:` ব্লকের ভেতর অবস্থান করতে হবে।

## ৮. সিনিয়র আর্কিটেক্ট ইন্টারভিউ কিউএ (Staff-Level Interview Q&A)

### প্রশ্ন ১: FastAPI কীভাবে একটি জেনারেটরের `yield`-এর পর এক্সেপশন হ্যান্ডেল করে? ইন্টারনাল মেকানিজম কী?
**উত্তর**:  
FastAPI ডিপেনডেন্সি কল করার সময় পাইথনের ইন্টারনাল `contextlib.AsyncExitStack` ব্যবহার করে। যখন কোনো ডিপেনডেন্সি জেনারেটর (`yield`) রিটার্ন করে, FastAPI সেটিকে এক্সিট স্ট্যাকের কনটেক্সট ম্যানেজার হিসেবে পুশ করে।  
যদি রাউটার হ্যান্ডলার এক্সিকিউশনের সময় কোনো এক্সেপশন ছোড়ে, FastAPI ইন্টারনালি সেই জেনারেটরের ওপর `gen.throw(exc)` মেথড কল করে। এর ফলে জেনারেটরের ভেতর ঠিক `yield` স্টেটমেন্টের পয়েন্টে সেই এক্সেপশনটি উদয় হয়। ডেভেলপার যদি `try...except...finally:` ব্লক রাখেন, তবে এক্সেপশনটি ধরা পড়ে, রোলব্যাক এক্সিকিউট হয়, এবং `finally:` ব্লক দিয়ে নিরাপদে রিসোর্স ক্লোজ হয়ে যায়।

### প্রশ্ন ২: ব্যাকগ্রাউন্ড টাস্ক (`BackgroundTasks`) চলাকালীন কি `yield` ডিপেনডেন্সির ডেটাবেজ সেশন খোলা থাকে?
**উত্তর**:  
**না, এটি একটি অত্যন্ত সাধারণ কিন্তু ভয়াবহ প্রোডাকশন ভুল!**  
FastAPI-তে ডিপেনডেন্সির `yield`-এর পরবর্তী টিয়ারডাউন কোডটি রান হয় ঠিক যখন রাউটার হ্যান্ডলার রিটার্ন করে কিন্তু ব্যাকগ্রাউন্ড টাস্ক শুরু হওয়ার **পূর্বে**। অর্থাৎ রেসপন্স ক্লায়েন্টের কাছে পাঠানোর সাথে সাথেই `get_db()` বা `get_transaction_context()`-এর `finally:` ব্লক রান হয়ে ডেটাবেজ কানেকশন ক্লোজ করে দেয়।  
যদি আপনি ব্যাকগ্রাউন্ড টাস্কের ভেতর সেই ক্লোজড সেশন পাস করেন, তবে টাস্কটি `StatementError: session is closed` দিয়ে ক্র্যাশ করবে। ব্যাকগ্রাউন্ড টাস্কের নিজস্ব সেশন তার নিজের ভেতর ওপেন ও ক্লোজ করতে হবে।

### প্রশ্ন ৩: `yield` ডিপেনডেন্সির `except Exception:` ব্লকে এক্সেপশন ক্যাচ করার পর কেন অবশ্যই `raise` করতে হয়?
**উত্তর**:  
যদি আপনি এক্সেপশন ক্যাচ করে `raise` না করেন (যেমন শুধু `print(e)` লিখলেন), তবে পাইথনের চোখে এক্সেপশনটি সুরাহা হয়ে গেছে বলে গণ্য হবে (Exception Swallowed)।  
এর ফলে FastAPI মনে করবে রিকোয়েস্টে কোনো ভুল হয়নি এবং সে ক্লায়েন্টকে ভুলবশত `200 OK` সহ নাল বা ব্ল্যাঙ্ক রেসপন্স পাঠিয়ে দিতে পারে! অ্যাপ্লিকেশন এবং HTTP বাউন্ডারির মাঝে স্বচ্ছতা বজায় রাখতে (Exception Transparency) রোলব্যাক সম্পন্ন করেই অবধারিতভাবে পুনরায় `raise` করতে হবে যাতে FastAPI-র ডিফল্ট বা কাস্টম এক্সেপশন হ্যান্ডলার সঠিক HTTP স্ট্যাটাস কোড (যেমন 404, 409, 500) ক্লায়েন্টকে ফেরত দিতে পারে।

## ৯. শিক্ষানবিস আর্কিটেক্টের চেকলিস্ট ও টেকঅ্যাওয়ে (Operational Checklist)

- [x] **Always Wrap Yield in `try...finally:`**: যেকোনো জেনারেটর ডিপেনডেন্সি যা ডেটাবেজ কানেকশন, ফাইল পয়েন্টার বা ট্রানজ্যাকশন ম্যানেজ করে, তার ক্লিনআপ কোড অবশ্যই `finally:` ব্লকে রাখুন।
- [x] **Always Re-raise Caught Exceptions**: এক্সেপশন হ্যান্ডলিং ব্লকে রোলব্যাক বা লগিং করার পর অবশ্যই `raise` কিওয়ার্ড ব্যবহার করুন যাতে এক্সেপশন হারিয়ে না যায়।
- [x] **Assert Zero Leaks in Stress Tests**: টেস্ট স্যুইটে শুধু স্ট্যাটাস কোড দেখবেন না; স্ট্রেস টেস্টের শেষে কানেকশন পুলের সাইজ বা `active_count == 0` কিনা তা পরীক্ষা করুন।
- [x] **Couple Auth and State Fixtures**: টেস্টে যখনই অথেন্টিকেশন হেডার ব্যবহার করবেন, নিশ্চিত করুন যে প্রয়োজনীয় ইউজার এন্টিটি মেমোরিতে আগেই সীড করা হয়েছে।
- [x] **No DB Session in Background Tasks**: ব্যাকগ্রাউন্ড টাস্কে কখনো রিকোয়েস্ট-স্কোপড `yield` ডিপেনডেন্সির ডেটাবেজ সেশন রেফারেন্স পাস করবেন না; ব্যাকগ্রাউন্ড টাস্কের জন্য স্বাধীন সেশন কনটেক্সট ব্যবহার করুন।
